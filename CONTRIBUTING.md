# Contributing

Changes use task branches and pull requests. Generated GDS projections
(`AGENTS.md`, `.claude/CLAUDE.md` and `.gds` compiled files) are regenerated by
GDS and must not be edited by hand.

Keep repository history explicit and reviewable:

- each commit must represent one coherent, independently understandable change;
- preserve the commits from a pull-request branch in `main`;
- merge pull requests with a merge commit only, after all required checks pass;
- do not use squash merges, rebase merges or direct pushes to `main`.

Before proposing a change:

```bash
make verify
```

For lifecycle or reconciliation changes, add tests for success, cancellation,
duplicate delivery, timeout, restart and cleanup behavior. A new external side
effect must have an idempotency key, bounded timeout, durable ownership and a
reconciliation rule.

Configuration changes fail closed. They must not introduce raw secrets, floating
production versions, host socket passthrough, persistent workspaces or a route
from general workers to management/production networks.

Architecture changes need an ADR. Performance claims need a reproducible
benchmark with median, p95, cold/warm state and hardware allocation.
